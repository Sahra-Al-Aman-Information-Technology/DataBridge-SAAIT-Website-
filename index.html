STEP-BY-STEP WORKFLOW

From Source Connect to Power BI in 6 Automated Steps

Zero complex YAML, zero brittle Python scripts, zero maintenance overhead.

01

Register Sources

Connect to Oracle, SQL Server, Excel files (.xlsx/.csv), and SharePoint lists with centralized credential management.

02

Configure Table Extraction

Map each source table individually in the UI—define column selection, load strategy (Full, Append, Merge), tracking columns, and primary keys.

03

CSV Staging & Warehouse Load

Extracts data on demand or schedule, stages it as a CSV, and loads into target warehouse (automatically creating destination tables if missing).

04

Execute Stored Procedures

06

FREQUENTLY ASKED QUESTIONS

Enterprise Data & IT Architecture FAQs

DataBridge supports 3 load strategies: Full Load, Append, and Merge. In Append mode, DataBridge uses a tracking column and automatically switches to Merge if today's data is already present in the target warehouse, preventing duplicates by upserting based on a Primary Key.
DataBridge registers source database stored procedures mapped to projects. Procedures are assigned sequence numbers and parallel groups—allowing independent procedures to run concurrently while dependent steps wait for prior steps to finish. Every run is logged.
DataBridge supports Oracle, SQL Server, Excel files (.xlsx / .csv), and SharePoint lists as data sources, and loads directly into Oracle and SQL Server target warehouses.
After extraction, DataBridge authenticates via Azure AD (MSAL / service principal with Client ID, Tenant ID, Client Secret stored centrally), calls the Power BI REST API, and polls until the semantic model refresh completes or fails—logging results in the Transaction Logs view.
